# CLEAN CORE BEST PRACTICES & ANTI-PATTERNS:-

BEST PRACTICE: ATC IN CI/CD :-
-> Mandate ABAP Test Cockpit checks in every code pipeline. Treat ATC violations as build failures, not optional warnings. 
-> This single practice prevents 90% of clean core regression.

BEST PRACTICE: RETIRE BEFORE BUILDING :-
-> Before approving any new extension, review SCMON usage data for existing objects. 
-> Retire unused custom code first—new requirements are often already met by under-utilised standard functionality.

ANTI-PATTERN: ‘JUST THIS ONCE :-
-> The most dangerous clean core anti-pattern is approving a single exception without governance. 
-> Each undocumented exception seeds the next five. Governance discipline must be absolute from day one.

ANTI-PATTERN: BTP WITHOUT API DESIGN :- 
-> Moving custom logic to BTP without proper API design replicates technical debt in the cloud. -> BTP extensions must be built on versioned, documented stable APIs—not quick-and-dirty REST calls.

# Usage Data Collection Tools & Techniques :-

SCMON - Statement Count Monitor :-
-> Activate SCMON in the production system to capture execution frequency per ABAP object 
-> This is the primary tool for identifying actively used VS Dormant custom code

Custom Code Migration App :-
-> Available in SAP Fiori for S/4HANA, this app imports SCMON data and ATC results to provide a prioritized remediation backlog with usage frequency and finding severity

Usage Data Collection Period :-
-> Run SCMON for a minimum of 6-12 months covering full business cycles (month-end, year-end, seasonal peaks) to ensure accurate frequency data before making retirement decisions

Frequency Thresholds :-
-> Establish threshold policies: 0 executions = candidate for retirement; <10/year = low priority;> 100/month = high priority for immediate remediation and cloud compatibilty

Dependency Analysis :-

# Custom Code Adaption Strategies :-

Replace Obsolete APIs :-
-> Identify and replace deprecated function modules, BAPIs, and transaction calls with S/4HANA-released APIs.

Use ATC findings to determine recommended replacements
Ensure compatibility with future upgrades


ABAP CLoud Migration :-
-> Refactor legacy ABAP code to align with the ABAP Cloud development model.

Use ABAP Objects (Classes) instead of procedural code
Implement RAP (RESTful ABAP Programming Model)
Access data via released CDS views only


Table Access Remediation :- 
-> Eliminate direct database access to application tables.

Replace SELECT statements with CDS views or APIs
Respect authorization annotations like @AccessControl.authorization
Ensure secure and compliant data access


Fiori - Enable Custom UIs :- 
-> Modernize legacy UIs for better user experience and maintainability.

# Legacy Modification Remediation

Modification Classification:
-> Categorize all modifications into: User Exits, Customer Exits, BADIs (Classic & New), Implicit/Explicit Enhancements, and Copies (Z-copies of SAP standard programs). Each has a different remediation path.

BADIs – Preferred Pattern:
-> New-style BADIs (implemented via SE19) are the preferred enhancement technique. Migrate classic BADIs and customer exits to equivalent new-style BADIs or SAP Extension Points where available.

Copies of Standard Objects:
-> Z-copies of SAP standard reports or function modules receive no SAP corrections. Review each copy against current standard functionality — most can be replaced with Fiori apps or standard reports.

Implicit Enhancements – Risk Assessment:
->Implicit enhancements inject code at SAP-defined hook points without explicit SAP approval. Validate each against the S/4HANA compatibility check and refactor to explicit BADIs or SAP BTP extensions.

Modification Adjustment Procedure:
-> For unavoidable modifications, follow SAP's Modification Adjustment procedure during upgrades using transaction SPDD (data dictionary) and SPAU (repository objects) to re-apply and re-test.
