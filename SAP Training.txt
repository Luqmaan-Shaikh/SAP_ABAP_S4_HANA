# ABAP -

-> ABAP Source code consists of either a Statement or a comment

-> Statements - Collection of Operators , Operands , Variables and Keywords. EX :- c = a + b  
-> Comments :- Non executable statements . To comment we use ASTERIK (*----*). EX :- * This is a Comment * 


-> Operators :- 
	- Mathematical (Addition, Subtraction, Multiplication, Exponential, Division, Mod)
	- Comparative (less then , less than equal to , greater than , greater than equal to , equal to , not equal to)
	- Logical (AND, OR, NOT)

-> Operands :- variables which we need to perform particular operations

-> Variables :- Name given to Memory Location

-> Keywords :- Identify type of Statements (C2 B3 E O)
	- Calling
	- Controlling
	- Declaration :- used to declare variable in ABAP (Data, Parameter, Tables, Types, etc)
	- Definition 
	- Database
	- Events
	- Operations


-> Data Types :- 

1. Numeric Data Types 
	- Integer I
	- Float F
	- Packed Decimal P

2. Character Data Types 
	- Char C (Alpha - Numeric) (Integer + Characters)
	- Numeric Char N
	- Date D
	- Time T


- Int, Float, Date, Time -> Fixed Length Data Type
- Rest are -> Variable Length Data Types


NOTE -> Everything you write in ABAP MUST END with a FULL STOP (.)


# Syntax of -

1. Integer (I) 

-> Data <variable_name> type I.
Ex. data A type I.
Initial / Default value of Integers is '0'


2. Float (F) 

-> Data <variable_name> type F.
Ex. data A type F.
Initial / Default value of Float is '.00'


3. Packed Decimal (P) 

-> Data <variable_name> (<length>) type P decimals <no>.
Ex. data A(10) type P decimal 3.
Initial / Default value of Packed Decimal is '.000' (number of decimals)



4. Char (C) (Alpha Numeric)

-> Data <variable_name> (<length>) type C.
Ex. data A(5) type C.
Initial / Default value of Char is 'Space / Empty'


5. Date (D)

-> Data <variable_name> type D.
Ex. data A type D.
Initial / Default Format of Date is 'YYYYMMDD' -> (20140425)


6. Numeric Char (N) (Ex. Contact Numbers , Bank Account Numbers)

-> Data <variable_name> (<length>) type N.
Ex. data A(10) type N.
Initial / Default Value of Numeric Char is '000' (Based on Length)


7. Time (T)

-> Data <variable_name> type T.
Ex. data A type T.
Initial / Default value of Time is '000000'. Format -> 'HHMMSS'

# SQL :- 

1. DDL :- Create , Alter

3. DCL :- Commit , Rollback


- SQL is Database Dependent and SAP is Database Independent

-> SAP doesn't support SQL

-> Open SQL support DDIC (Data Dictionary) -> which is used to create or alter table




------>>>>>> DATA DICTIONARY :-

- Central source of DBMS 
- Main functionality of DDIC is to create or alter tables

-> 2 ways to create DB Table :-

1. Direct method / pre defined / built in [We Don't use this]
2. Data Element Method (TD Approach , BU Approach)



-> Technical Requirements to create Table :- 
	- Name of table starts with y or z 
	- Provide list of fields, data types and lengths
	- Provide the delivery class
	- Provide the Technical settings



-> Delivery Class :-
- It defines the owner of the tables as well as it controls the transport of the data from one table to another table 
- Technical settings is nothing but the combination of DATA CLASS and SIZE OF THE CATEGORY


-> Data Class :- 
- Data Class defines the physical area of the DB in where our table is logically stored

- Some of the important Data Classes are :-

1. APPL 0 - Master Data = Access Frequently But Updates Rarely (Customer master data, employee master data)
2. APPL 1 - Transaction Data = Access Rarely and Updates Rarely (Sales order , Purchase Order Data) . Technical Data is Dependent Data.
3. APPL 2 - Organization Data = Access Frequently But Updates Rarely (Company Data , Branches Data) . Organizational data is created at the time of system configures.



-> Size Category 
- It determines the space require for the table. 
- Size category : 0
- Each table must have at least one field as primary field that should be the character data type that should be character data type that should in th first field in the table

# Types of Table :-

1. Transparent Tables [We use this]

-> One - to - One R/s
-> If you create one transparent table in DDIC, then it'll store like only one data table in the data base
 
2. Cluster Tables

-> Many - to - One R/s
-> If you create many clustered tables in DDIC then they will form a table cluster and store in the data base
-> Buffering isn't possible for clustered table. For this reason only fetching the data from clustered table takes more time
-> Clustered table is suitable when you fetch the fewer amounts of data from more fields

3. Pool Tables

-> Many - to - One R/s
-> If you create many pooled tables in DDIC, then they will form form like a table pool and stored in the data base
-> Pooled tables are suitable when we fetch the large amount of data from fewer fields

NOTE:- Joins aren't possible for clustered and Pooled Tables

# Internal Tables ******************** :-

1. Internal Tables is the collection of Records.
2. IT are Temporary Tables. Means Data in IT wont be saved anywhere in SAP.
3. IT are Dynamic Memory Location. Means we don't have to provide size of IT.
4. Scope of IT is up to that program.
5. Placing Data to IT as well as getting data from IT is always record by record.


#           Database Table                  VS             Internal Table

- DBT are Permanent Storage Location        VS       IT are Temporary Storage Location
- We can Access DBT from anywhere in SAP    VS      We can Access IT within the Program only
- We must provide Size of DBT               VS      IT are Dynamic, Need not provide the size


# Syntax of declaring IT :-
-> 
Data <internal table> LIKE table of <work area>.

# Ex:- 
-> 
Data IT like table of WA.

# Syntax of accessing fields from Work Area
-> 
<work area name> - <field name>.

# Ex :-
-> 
WA - Eid.

NOTE -> APPEND is the Keyword to Transfer the data from work area to IT


# Ex :- 
->
Data: Begin of emp,
      eid(10) type c,  
      ename(25) type c,
      ecity(30) type c,
      ecntno(10) type numc,
      End of emp.
Data IT like table of WA.
WA-Eid = '1'.
WA-Ename = 'Ali'.
WA-Ecity = 'Hyd'.
WA-Ecntno = '0000000000'.
APPEND WA to IT.
WA-Eid = '2'.
WA-Ename = 'Luqmaan'.
WA-Ecity = 'Mumbai'.
WA-Ecntno = '1111111111'.
APPEND WA to IT.
Loop at IT into WA.
Write:/ WA -Eid, WA - Ename, WA - Ecity , WA - Ecntno.
Endloop.

# Syntax :-
->
Data <IT> like standard table of <work area>.


# Sorted IT :-

-> May or may not accept Duplicate Records
-> Here we must specify at least one field as Unique / Non-Unique
-> Passing Data from work area to IT is always through 'Insert' Keyword
-> Searching of a Record is Binary Search

# Syntax :-
->
Data <IT> like sorted table of <work area> with unique / non-unique key <filed>.

#Ex :-
->
Data IT like sorted table of WA with unique key Eid.


# Hashed IT :-

-> Wont accept Duplicate Records
-> Here we must specify at least one field as Unique
-> Passing Data from work area to IT is always through 'Collect' Keyword
-> Searching of a Record is Hash Algorithm

# Syntax :-
->
Data <IT> like hash table of <work area> with unique key Eid.


# Kind is the keyword which returns type of IT 
- Standard (T) , Sorted (S) , Hash (H)

# Lines is the keyword which returns the no of records in IT

# Syntax :-
->
Describe table <internal name> KIND <variable1> LINES <variable2>.

# Ex :-
->
Describe table IT_KNA1 KIND v1 LINES v2.

NOTE -> By Default variable is the character data type and length is 1
NOTE -> By Default IT is Standard IT (T)

## Macros :-

-> Macros are used to perform the arithmetical operations
-> Macros can take upto 9 place holders (&1, &2, .... &9)
-> If you want to maintain the same set of statements more than one location of the same program instead of this we maintain those statements in macro definition later we call the same macro definition from different locations of the same program

# Syntax of calling the macro :-
->
<macro name> <place holder value> <place holder 2 value>.

## Subroutines :- 

-> Subroutines are procedures
-> That we can define if any ABAP program & calling from the same or some other ABAP program
-> Procedures is the collection of statements

# Syntax of defining the subroutine :-
->
Form <form name / subroutine name> using <IV 1> type <DT> <IV 2> type <DT> ... changing <OV 1> type <DT> <OV 2> type <DT> ...
---
---
---
Endform.

# Syntax of Calling the subroutine :-
->
Perform <form name> using <IP 1> <IP 2> ... <OP 1> <OP 2> ...

NOTE -> In Subroutine calling is the first & definition is the next
     -> In Subroutines all the using parameters are called input parameters
     -> All the changing parameters are called as output parameters
     -> We cant place any executable statement after the definition of the subroutine

# 2 Types :-

1. Internal Subroutines :-
-> Its nothing but the definition of the subroutines as well as calling of the subroutine must be in the same program

2. External Subroutines :-
-> Its nothing but the definition of the subroutines taken from one program & the calling of the subroutine is taken from some other ABAP program

# Syntax of calling the external subroutine :-
->
perform <form name> in program <program name> using <ip1> <ip2> ... changing <op1> <op2> ...



## Diff btw Macros 							VS 	  Subroutines :-

1. In Macros definition and calling in the same program                 VS        may / may not in the same program
2. In Macros definition should be first and calling should be next      VS        Calling should be first and definition should be next
3. Macros contain upto 9 inputs                                         VS        Can contain any number of input
4. After definition of macros we can place any executable statement     VS        we cant place any executable statement
5. Macros are used in HR-ABAP VS both HR-ABAP & ABAP


# Termination of subroutine :-

-> Subroutines normally ends with endform
-> If you want to terminate the subroutine earlier then we use exit or check command
-> Exit command is used to terminate the subroutine unconditionally
-> Check commands is used to terminate the subroutine conditionally

- Diff types of programming structures
1. Unstructured
2. Procedural
3. OOP


1. Unstructured Programming :
-> Entire Prog contains only 1 main prog
-> Same set of statements is placed in multiple locations of the same prog
-> Its very difficult to maintain if the prog becomes very large

2. Procedural Programming :-
-> Entire prog is splitted into smaller program
-> Same set of statements is placed in placed in a procedure (Subroutines or FM) & later we call the same procedure from diff locations of the same prog
-> All the subroutines & FM can access the global declrations
-> It takes little bit extra time to enhance the existing functionality

3. Object Oriented Programming :-
-> Entire prog is visualized in terms of class & objects
-> All the modules cant access the global declarations
-> It takes very less time to enhance the existing functionality

1. Better programming structure
2. Most stress on data security & access
3. Reduce the redundancy of code
4. Data Abstraction & Encapsulation
5. Inheritance and Polymorphism

-> These are special type of methods

-> These methods are mainly used to set default values in a class
-> The name of the constructor method is 'Constructor'

-> These are executed only once
-> The name of the static constructors is 'CLASS_CONSTRUCTOR'

## Cross Application :-

-> Cross Appln is the concept to exchange the data among the systems
-> ALE is Appln Link Enabling is an SAP technology to support cross appln
-> Uses IDOC to Support the cross apllns
-> IDOC Interface Document is the carrier to carry the data from one system to another system
-> SAP can understand only the IDOC format, when it communicates with any other system


-> Irrespective of the receivers, the ABAPER job in sender system is to generate the IDOC
-> The process of generating the IDOC is nothing but out bound process
-> Irrespective of the senders, the abaper job in receiver system is to collect the data from IDOC
-> The process of collecting the data from Idoc is nothing but in bound process

# Runtime Components of IDOC :-

1. It generates a simple Idoc number, which is 16 digits
2. It generated 3 types of records
	- Control records 
	- Data records 
	- Status records



1. Control Records :-

-> Control Record specifies the sender as well as receiver information
-> It generates only one control record
-> This information will be saved on EDIDC table


2. Data Records :-

-> It specify the data which is send by the senders system
-> It generates any number of data records
-> This information will be saved on EDIDD table


3. Status Records :-

-> It generates Status Code for each and every stage of transferring data
-> It generates any no of status records
-> This information will be saved on EDIDS table


## Status Codes are 

1. Outbound Status (0 - 49)
2. Inbound Status (50 - 75)


Note -> The linking between EDIC, EDIDD and EDIDS is the IDOC number.

-> BAPIs are used to connect from SAP to SAP as well as SAP to Non-SAP

-> BAPIs are defined as an API Method of SAP Objects
-> These methods and their objects are stored as well as maintained in BOR (Business Object Repository)
-> BOR taking care about version change management (whenever the version is changed if any changes required in BAPI those changes is done by BOR)
-> BAPIs are also called as one of the Remote Function Module


## 		BAPI 							VS 				BDC

1. Used to upload the data from file to SAP system directly 		VS  	from file to SAP through screens
2. Faster 								VS	Slower
3. Never cause to terminate the program when ever error occurs in the   VS 	Some times BDC Open Group BDC insert BDC Close Group may cause to terminate the program
   BAPI it is simply written those errors through written parameters 
4. Performs own Authorization checks to validate the user 		VS 	We provide the authority check to validate the user 
5. In BAPI Flat File Fields are varying 				VS 	Fixed
6. Whenever the version is changed we no need to change the code 	VS 	Sometimes we need to change the code



## Some of the important points related to BAPI: - 

1) BAPI mustn't contain call transaction. 
2) BAPI mustn't invoke commit work instead of commit work we call the BAPI
TRANSACTION_COMMIT function module. 
3) BAPI structure mustn't contains includes. 
4) There is no functional dependences between any two BAPI's. 
5) BAPI never calls to terminate the program. Whenever an error occurred in BAPI it written those 
errors through written parameter. 
6) BAPI must not contain dialogue programs. 
7) BAPI mustn't contain Submit reports.

## REST Architecture :-

-> Given below are the components of the REST Architecture 

1. Resources :-

-> In REST, both the state and the functionality are presented as resources. Resources are the ky element of RESTful design, as opposed to 'methods' or 'services' used in RPC and SOAP Web Services

-> RPC, calls like 'getProductName' and 'getProductPrice' are not used in REST. You view the product and data as a resource should contain all the required information

2. Web of Resources :-

-> It means that a single resource should not contain detailed data and it contains links to additional web pages 

3. Client - Server :-

-> In REST client - server model, one component server can be the other component client 

4. No Connection State :-

-> Each request should contain details about the connection to each client and should not reply on the previous connections tl the same client 

5. Cacheable :-

-> The protocol must allow the server to explicitly specify which resources may be cached, and for how long

6. Proxy Servers :-

## GET_ENTITYSET Method :-

-> The GTE_ENTITYSET Method in the data provider class is called when you specify an entity set name without any parameters in the URL, and returns all entities in the specified entity set

-> After the runtime data provider class is created, the method is initially an empty shell
-> The base class implementation does nothing, so the derived runtime data provider class must redefine this method to implement the business logic that enables the service to return entity sets

-> GET_ENTITYSET is a general-purpose method for delivering any entity set
-> The GET_ENTITYSET method in your runtime data provider class responds to requests for any of the entity sets defined in the model class

=> To provide the functionality for getting an entity set :-

1. Redefine the GET_ENTITYSET method in the general runtime data provider class to dispatch requests to the GET_ENTITYSET methods data provider classes that are specific to each entity type

2. Implement the GET_ENTITYSET methods for each entity-type-specific runtime data provider class


-> For a service to provide delta-querying capabilities, its GET_ENTITYSET method must issue a delta token and return it as part of the response
-> This delta token is picked up by the client and submitted with subsequent requests to retrieve the data that has changed since the token was issued
-> Add the delta token to the ES_RESPONSE_CONTEXT parameter, which is available in the delta token

## Deep Entity 

-> In SAP OData, the concept of 'deep entity creation' refers to creating or updating multiple entities in a single request by including related entities in the payload

-> This approach offers several benefits :-

1. Reduced Network Overhead :- 
- Deep entity creation allows us to minimize the number of requests sent over the network 
- Instead of making separate requests for each entity, we can include, all the related entities in a single request payload
- This reduces network latency and improves overall performance

2. Atomicity and Consistency :-
- Deep entity creation supports the notion of atomic operations
- It ensures that either all the entries in the request are created successfully, or none of them are created 
- This helps maintain data consistency and integrity within the SAP system

## Open Dataset :-

-> Open Dataset statement in ABAP is used for opening a presentation server file in the program 
-> For closing the file CLOSE DATASET statement is used 

# Syntax :-

OPEN DATASET <dsn>
[FOR INPUT | OUTPUT | APPENDING | UPDATE]
[IN BINARY MODE | IN TEXT MODE | IN LEGACY BINARY MODE | IN LEGACY TEXT]
[REPLACEMENT CHARACTER <rc>]
[IGNORING CONVERSION ERROS]
[AT POSITION <pos>]
[TYPE <c>]
[MESSAGE <mess>]
[FILTER <filt>].


-> Without any additional the OPEN DATASET statement open a file for reading purpose in binary mode
-> For other purposes we need to specify the statement with the proper additions.

FOR OUTPUT: Open a file for writing
•	Will create a new file, if the file not exists
•	If the file is already opened, then the writing position set at the starting of the file
•	If the file is not opened already, the contents of the file will be deleted.
•	In this mode writing always start from the beginning of the file.
FOR INPUT: Open an existing file for writing.
Only the difference with OUTPUT addition is, it won’t create new file if it not exists.
FOR APPENDING: Open a file for writing at the end of file.
•	Will create a new file, if the file not exists
•	If the file is already opened, then the writing position set at the end of the file
•	In this mode writing always start from the end of the file.
IN BINARY MODE: This addition opens the file as a binary file. In this mode, the read and write operation doesn’t require interpreting the file contents, the entire data is used in an unchanged form.
IN TEXT MODE: This addition opens the file as a text file. In this mode, read and write operations deal the contents of the file in a line by line way. The addition ENCODING also used with for specifying the character representation for the file.
AT POSITION: This addition is used for specifying an exact position in bytes to read or write. For an example AT POSITION 10 will skip first 10 bytes in the file and the initial read or write operation will start from this position only.
TYPE: This addition is used for specifying further file attributes for passing to the operating system.
MESSAGE: This addition is used for storing the system messages like error messages at the time of opening files.
FILTER: This addition is for specifying the system commands like compress in UNIX.
 
It always a good practice to use CLOSE DATASET after the processing with the file opened with OPEN DATASET.

## CDS Join Types :-

=> CDS Join Types with Examples:

1. Inner Join
->An Inner Join combines records from two or more tables only when there is a match in both tables. If there is no match, the rows are not included in the result set. It is one of the most commonly used join types and works well when you need data that is present in both tables.

- Cardinality:
-> Ø 1:1 or 1: N: Depending on the relationships between the tables, an inner join can have a one-to-one or one-to-many relationship.

- Use Case:
-> An Inner Join is useful when you only want records that have related data in both tables. For example, if we want to get purchase order details (from EKKO and EKPO) for items that are actually ordered, an inner join would be the appropriate choice.

- Example:
-> Let’s say we want to get purchase order details (EKKO) along with the items (EKPO) from a specific company code.

2. Left Outer Join
-> Retrieves all rows from the left table and matching rows from the right table. If no match exists, the result includes null values for the right table.

- Cardinality and Behavior:
-> 1:1: Keeps unmatched rows with null values.
-> 1: N: Ensures all rows from the left table appear, even if the right table has no match.
-> N:M: Needs careful design to avoid unnecessary data duplication.

- Use Case:
-> Fetch all deliveries from LIKP, including their corresponding items in LIPS, even if items are missing.
-> Retaining Non-Matching Records from Left Table

3. Right Outer Join:
-> The Right Outer Join is similar to a Left Outer Join but focuses on retaining all rows from the right table.
-> Retrieves all rows from the right table and matching rows from the left table. If no match exists, the result includes null values for the left table.

- Cardinality and Behavior:
1. 1:1: Returns rows even if the left table has no match.
2. 1: N: All rows from the right table appear, matched with rows from the left.

- Use Case:
-> Combine open items with cleared items, retaining all cleared items with BSID, BSAD Tables.
